# TeamWiki design

Build a local portfolio-ready collaborative knowledge base using Python >=3.12, FastAPI, SQLAlchemy 2 async, PostgreSQL, Redis, Celery and React/TypeScript. Prioritize tenant security, atomic document updates and reliable asynchronous imports. User requested autonomous implementation, so routine architecture choices below are implementer defaults.

## Approach
Use a modular monolith and a separate worker sharing service functions. Microservices and realtime CRDT are excluded by scope. SQLite may only serve isolated tests if PostgreSQL cannot run, never as an advertised production replacement. Browser client uses same-origin API through Vite/Nginx.

## Models and invariants
UUID string IDs (36 chars): User; AuthSession (revocable JWT jti); Workspace; WorkspaceMember (unique workspace/user); Invitation (hashed token, email, role, expiry, one use); Page (workspace, parent, title, content, version, deleted_at, tags JSON); PageRevision (unique page/version immutable snapshot incl title/content/tags/parent/deleted flag); PageLink (source, target nullable, raw target, state, source_version); AuditLog; ImportJob; OutboxEvent. Page tree parent and page link target use composite workspace/page foreign keys. Only owner may change admin roles; admin manages editor/viewer only; owner cannot be removed/demoted. All members can read workspace pages, editor+ can write, admin+ manage imports/audit.

## API contract (all IDs strings, JSON snake_case)
Prefix /api. Auth: POST /auth/register {email,password,name}, POST /auth/login {email,password}; return {user:{id,email,name}} and HttpOnly JWT session cookie; GET /auth/me -> user; POST /auth/logout -> 204. Cookie SameSite=Lax, Secure production; mutating browser requests verify Origin. Login returns optional csrf_token if needed; client uses same-origin requests credentials include.
Workspaces: GET /workspaces -> array {id,name,role}; POST {name} -> workspace incl role. GET /workspaces/{wid}/members -> array {user_id,email,name,role}; PATCH /members/{uid} {role}; DELETE same; POST /invitations {email,role} -> {token,...}; POST /invitations/accept {token} -> workspace.
Pages: GET /workspaces/{wid}/pages?deleted=false -> flat array Page (tree via parent_id). POST same {title,content,parent_id?,tags?} -> Page. GET /pages/{pid} -> Page. PATCH same {version,title?,content?,parent_id?,tags?} -> Page. DELETE same?version=N -> Page soft-deleted; POST /pages/{pid}/undelete {version} -> Page. Page={id,workspace_id,parent_id,title,content,tags:string[],version,deleted_at,created_at,updated_at,created_by,updated_by}. 409 error detail contains {code:'version_conflict',current:Page,submitted_version:N}.
GET /pages/{pid}/revisions -> array snapshots; GET /revisions/{version}; POST /revisions/{version}/restore {version:currentVersion} -> new Page.
GET /pages/{pid}/links -> {outgoing:[{id,source_id,target_id,target_title,raw_target,state,source_version}],backlinks:same[]}. Wiki syntax [[Title]], [[id:uuid|Label]]. Duplicate title allowed: new title link ambiguous if >1 active matches, unresolved if 0. Resolved links remain pinned by target ID through renames/deletes (state deleted) and restores. Source saves preserve bindings by raw target. Index is synchronous under workspace row lock, so out-of-order async jobs cannot overwrite newer links.
GET /workspaces/{wid}/search?q= -> array Page + rank. GET /graph -> {nodes:[{id,title}],edges:[{source,target}]}. GET /pages/{pid}/export -> markdown download. GET /workspaces/{wid}/export -> zip. POST /imports multipart file + Idempotency-Key -> ImportJob; GET /imports/{jid} -> {id,status,total,processed,error,result,...}. GET /audit -> array events.

## Reliability
Version addressed Redis keys tw:{wid}:page:{pid}:v:{version}; authorize membership and read current version/deletion from DB before using cache. TTL + jitter, short cache timeouts, degrade to DB. This avoids read-fill invalidation races and stale deletion/tenant leakage. On successful commit evict previous key best effort.
Use conditional UPDATE for every page mutation. On CAS failure 409, no revision/audit/link writes. Hold workspace row lock when restructuring/indexing links to avoid cross-document races. Tree cycle validation performed inside this lock. Revisions represent complete resulting states.
Import accepts bounded UTF8 markdown or ZIP. Reject absolute paths, traversal, symlinks, encrypted files, duplicates, excessive count/ratio/expanded size. Store validated payload in job JSON. Job creation and Outbox row commit together. Separate periodic dispatcher publishes and marks published only after broker acknowledgement; crashes may duplicate. Worker row-locks job and atomically imports every page plus job completion in a transaction; unique import-job/item keys and completed check ensure idempotency. Retry state records error without overwriting completed status. Stale queued jobs are periodically re-dispatched. Permissions checked again at execution.
