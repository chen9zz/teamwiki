## Chinese search
- Keep PostgreSQL as the search engine and preserve English FTS behavior/ranking. Add pinned jieba application-side search tokenization for Chinese and mixed text, a weighted PostgreSQL vector/GIN index, and explicit reversible migration/backfill for existing pages.
- All creation, CAS updates, history restore and both import formats must update search fields in the same transaction as the page. Never use a late asynchronous indexing task. Tokenization must not block the API event loop; keep statement/lock/resource limits and document PostgreSQL vector/token limits honestly.
- Query and document normalization must agree. Test natural Chinese phrases, two-character terms, mixed Chinese/English, title priority, update/delete/restore/import visibility, tenant isolation and existing-page backfill. Do not claim semantic search, typo correction or arbitrary substring matches.

## Portable archive
- Preserve ordinary Markdown and strict generic Markdown ZIP imports and legacy GET export behavior. Add GET /workspaces/{wid}/export?format=teamwiki (legacy default format=markdown).
- New ZIP has root teamwiki.json with format='teamwiki', version=1, and pages entries {key,path,title,parent_key,tags,links}. key is an archive-local canonical UUID, path is pages/<key>.md. links entries {raw_target,target_key} only bind targets present in the archive. Do not export auth, membership, audit or revision history.
- Portable import validates the schema, exact referenced files, unique IDs/paths, parent existence/acyclicity/depth and link mappings against visible Markdown targets. Reject dangling or foreign manifest references, unsafe files/paths and ambiguous metadata. Use bounded limits: at most400 pages,20 tree levels,1MiB manifest,16MiB expanded bodies,2MiB per body/1M chars,8MiB uploaded/output ZIP; existing generic limits remain.
- Preallocate new page UUIDs and create parents before children. Remap visible explicit [[id:...]] references to new IDs without modifying fenced/inline/escaped code examples. Preserve internal title-link identity using validated initial bindings before reconciliation so same-title existing pages cannot steal imported relationships.
- Reuse ImportJob/Outbox atomicity, row locks and task/item unique keys. Existing payloads remain compatible. Whole import succeeds or rolls back, including generated pages, revisions, links, search fields and audit.
- Use one coherent database snapshot for export metadata, bodies and links; preflight page count and total body bytes before materializing bodies. ZIP compression runs outside the API event loop; add bounded per-process export admission. Small bounded exports remain request/response downloads, not Celery export jobs. No new object storage/middleware.
