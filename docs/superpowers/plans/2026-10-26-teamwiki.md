# TeamWiki Implementation Plan

> **For agentic workers:** Use executing-plans with parallel bounded ownership. User explicitly requested immediate autonomous implementation.

**Goal:** runnable secure collaborative knowledge base, verified against real infrastructure when possible.
**Architecture:** modular monolith; explicit database compare-and-swap; transactional revisions/links/audit/outbox.
**Tech Stack:** Python >=3.12, FastAPI, SQLAlchemy 2, PostgreSQL, Redis/Celery, React/TypeScript.
**Spec:** docs/superpowers/specs/2026-10-26-teamwiki-design.md

## Global Constraints
- Every tenant query includes membership verification and workspace ID.
- Backend authorization; Argon2 and revocable JWT cookie sessions.
- PostgreSQL schema changes through Alembic; async SQLAlchemy.
- Keep technology claims consistent with code and observed tests.

## Review Focus
- Forged IDs, demoted members and replayed sessions cannot bypass scope.
- Concurrent saves and restores produce one winner and coherent history.
- Rename/delete/restore and duplicate titles preserve safe link identity.
- Retry/duplicate import execution cannot duplicate pages; unsafe ZIP rejected.
- Redis read-fill races cannot cause stale document reads after update/delete.
