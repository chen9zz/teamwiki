# TeamWiki v0.3 Implementation Plan

> For agentic workers: use test-driven-development and independent ownership; root integrates and verifies before publishing.

**Goal:** Reliable hierarchical ZIP import, bounded frontend pagination and genuine full-stack browser regression.
**Architecture:** Existing FastAPI/SQLAlchemy monolith and real Compose stack, metadata tree pagination, Playwright Chromium against actual services.
**Tech Stack:** Existing Python/React/PostgreSQL/Redis/Celery stack, Playwright as a development dependency.
**Spec:** ../specs/2026-10-28-v03-design.md

## Global constraints
- Tenant scoping, four roles, atomic CAS and transactional import idempotency must remain intact.
- Preserve the existing demo environment; use isolated test databases and Compose project/port.
- Publish sanitized source and real results only, with GitHub noreply commit metadata.

## Review focus
- ZIP depth/path/casing/collision bounds and full rollback of generated directories.
- Pagination must not hide children, lose a saved parent or mix workspaces/pages.
- Query invalidation after imports and moves must refresh lazy tree collections.
- Browser tests need actual built frontend/API/Worker, reproducible fixtures and no response stubs.
- Retry/duplicate delivery and late failures must never duplicate or overwrite successful imports.
