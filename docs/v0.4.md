# v0.4：中文检索与可往返的知识库归档

## 中文和中英混合搜索

保留 PostgreSQL 全文检索，引入固定版本 jieba 0.42.1 的搜索模式（关闭 HMM），文档和查询使用同一套 NFKC、大小写归一化和分词规则。含汉字的查询走 `plainto_tsquery('simple', ...)`；纯英文继续使用原来的 `search_vector` 和 `websearch_to_tsquery`，保留英文引号、否定和长正文检索行为。两个向量分别使用 GIN，标题权重 A、正文权重 B；搜索始终验证成员并过滤当前空间及未删除页面。

页面创建、条件更新、历史恢复和导入时，分词字段与正文、版本、修订、链接同事务提交。索引不交给可能迟到的后台任务。分词在线程中执行，避免阻塞异步事件循环。`0003_chinese_search` 迁移分批回填已有页面，不改正文、业务版本或历史。迁移引用冻结的 `search_tokenizer_v1.py`；改变词典或算法时需要新版本及数据迁移。

中文索引有明确预算：正文前 32,768 字符；每字段最多 8,192 词元、96 KiB 分词输出；单词元最多 128 UTF-8 字节。原文完整保留，被截断或跳过词元时设置 `search_index_truncated`，界面会提示覆盖范围。超出词元预算的查询返回 422，不静默删词扩大结果。原有 PostgreSQL 向量表示仍有自身限制；确实触发 `tsvector` 大小上限的写入返回 413 并整体回滚。不是任意子串、语义搜索或纠错；分词及数据库词元边界会影响命中。

## 两种导出和兼容导入

| 格式 | 用途 | 保留内容 | 主要限制 |
| --- | --- | --- | --- |
| Markdown ZIP（默认） | 普通 Markdown 工具使用 | 每页正文，文件名含稳定 ID | 2,000 页、32 MiB 正文；平铺，无元数据往返保证 |
| TeamWiki ZIP | 搬迁一份当前活跃知识库 | 正文、标题、标签、父子层级、归档内已绑定链接身份 | 400 页、20 层、16 MiB 正文、8 MiB ZIP、1 MiB 清单；单页 2 MiB / 100 万字符 |

`GET /api/workspaces/{wid}/export?format=teamwiki` 返回可直接交给原有上传接口的 `.teamwiki.zip`。归档含根目录 `teamwiki.json`（`format=teamwiki, version=1`）和 `pages/<UUID>.md`。清单项包含 `key/path/title/parent_key/tags/links`；链接绑定为 `raw_target/target_key`。未知格式、重复 JSON 键、循环或悬空父节点、伪造链接、重复身份、额外/缺失文件及不安全压缩包都会拒绝。普通 Markdown/层级 ZIP 继续兼容原有规则和压缩比限制。

导入预分配新 UUID，按父节点顺序创建。归档内部的显式 ID 和已解析标题链接保留目标身份，目的空间的同名页面不能抢占这些绑定。指向归档外的显式 ID 统一映射为新的未绑定 ID，防止恰好引用目的空间已有页面。重写与链接解析共享可见 Markdown 规则，保留代码块、行内代码和转义示例；非标准 UUID 不会因归一化意外变成有效引用。未声明的普通标题链接仍按目的空间通常规则解析。

归档是当前活跃知识库的迁移格式，不包含成员、会话、历史版本、审计或已删除页面；不等于完整数据库备份。每次新任务都创建独立页面，不与已有页面合并。使用相同幂等键和相同上传内容重试会复用同一任务；Worker 的行锁、完成状态和唯一项目键防止重复消费。整个导入事务成功或全部回滚，进度仍通常是 0→N。

## 资源与并发边界

导出通过独立的 PostgreSQL `REPEATABLE READ READ ONLY` 快照统一读取元数据、正文及关系，避免并发修改产生清单与正文不一致。先聚合数量/字节上限再读正文；关系清单也先做预算检查。释放快照后在线程中压缩，每个 API 进程最多接纳两个工作区导出，忙时返回 503 和 `Retry-After: 1`。取消下载不会提前释放仍在压缩的槽位。它仍是有界同步下载，没有后台导出 Job 或对象存储。

这些措施控制单次任务和并发资源；不意味着单机无限扩容。导入仍持有空间排他锁，结构变更仍可能阻塞同空间写入；查询/分词和压缩仍消耗 CPU。连接池、在途上限、缓存故障回退、CAS 与 Outbox 的完整取舍见[并发方案](concurrency.md)。
